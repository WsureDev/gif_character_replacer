# GIF Web 测试台

## 使用流程

先在顶部“生图 Provider”选择接口，随后创建草稿。未选择也可准备离线草稿，但提交前需要选择 provider 并重新生成绑定该配置的草稿。

1. 上传 GIF 和 1–15 张角色参考图，也可选择项目已有素材。
2. 等待识别 GIF 信息，选择自动生成的分辨率档位，或在原图范围内输入自定义长边。选择保留帧数或目标 FPS；范围由当前 GIF 的真实帧数和时长计算。
3. 可配置输出画布宽高范围、每版帧数上限、分隔带、边距和替换提示词。每版帧数上限为 0 时按像素容量自动计算。
4. 点击“生成拼版预览 · 保存草稿”。此步骤完全离线，展示实际采样 GIF、分辨率、帧数、时长和所有拼版。点击版图可放大，预计张数即将发送的图片编辑请求数。
5. 勾选审核并点击 Submit。后台按全局并发额度生成、算法切帧、组装 GIF；每版并排显示输入拼版和返回图，以及状态、请求耗时和错误。即使切图失败，已经返回的图片也可以查看和放大。

页面顶部可配置全局生图并发，默认 **2**，允许 **1–120**，提供 2/3/4/5 快捷档位。设置保存到数据目录的 `queue-settings.json`，重启后继续生效；所有任务共享额度。降低额度不会中止已经发出的请求，后续请求等待额度释放。

每版支持“重试切图”（仅处理已返回图片，不调用生图接口）和“重新生图”（使用当前接口配置，新增 1 张请求）。失败任务可点“继续剩余任务”：先检查和恢复已有返回图，再生成未发送的版；已经发送但没有返回图的版需要单独手动重试。重试写入新目录，旧图片与上次完成的 GIF 保留；全部版完成后重新合成完整 GIF。

上传后本地分析会自动比较整个时间轴，页面展示变化密度和“保守保真 / 均衡推荐 / 优先省张数”档位；结果相同的档位合并显示。点击档位后采用智能变帧时长采样，再生成草稿审核。整个过程不调用生图或 LLM 接口。

## 实验：先确认一帧效果，再生成各版

在“成本与采样”开启“先确认一帧效果”（默认关闭），先生成离线草稿，再用帧编号或滑块从**当前采样后的完整时间轴**选一帧，编号从 1 开始并即时显示原帧。

1. 点击“试生成所选帧 · 1 张”：明确提交一次单帧生图。系统创建独立试生成任务，使用原草稿的 GIF、角色图和提示词快照，进入同一个全局队列。此时整段各版不会提交。
2. 比较原帧与试生成结果。可以打开试生成任务查看状态、返回图，失败时重切或手动重试；也可以回到原实验草稿换帧再试。每次新的生图请求按 1 张计算，本地重切不调用接口。
3. 点击“确认这张效果 · 生成后续草稿”：将看到的效果图保存为独立快照，为每版追加同一张效果参考图，并创建新的离线草稿。**确认不会发送后续生图请求**；旧试生成以后被重试，也不会改变已确认的草稿。
4. 审核新草稿与共同基准图，再 Submit 生成各版。输入中的原角色图负责身份，已确认效果图负责外观、比例、材质、配色、画风与光照处理；各帧的动作、表情、场景变化仍以原拼版为准。

首次成本是 **1 张试生成 + N 张版图**；多次试生成另计。所选帧仍占拼版中的一个格子，但最终成品直接使用确认的帧图，不采用该格再次生成的结果；其余帧按正常流程生成。若启用去重，所选帧对应的整组复用位置使用同一确认图。原有逐帧时长和循环保持不变；最终放回原尺寸时再统一缩放。

该实验最多上传 14 张角色参考图，为已确认效果图预留第 15 个位置。原实验草稿禁止直接 Submit；只有独立试生成和确认后的新草稿可以提交。选帧范围、已审核输入哈希、试生成所属任务及确认时的图片哈希都会校验；重复提交相同操作 ID 不会重复创建或发送任务。服务中断后不自动重发生图请求。

试生成及后续任务保留关联，可从页面返回原实验。需要调整采样或提示词时，返回原实验创建新草稿，避免把效果参考图误当成普通角色图沿用。确认图在新任务 `references/reference-N.png`，确认记录在 `references/anchor-approved.json`，两者纳入草稿哈希；每版请求保留该参考图和用途说明，最终组装报告以 `approved-reference` 标记直接复用的位置。

共同参考有助于减少跨版外观差异，但不保证动作衔接或所有细节完全一致；仍需检查最终动画。此功能测试使用模拟接口，不代表已经验证真实供应商的改善幅度。

## 实验：全局相似帧去重

“成本与采样”中可选关闭（默认）、自动推荐、仅完全重复、自定义评分阈值（98–100）。先执行现有分辨率/时间采样，再对整个采样动画查找可复用画面，不局限于相邻帧。关闭降帧即可保留原始全部播放位置；若同时使用降帧，还原的目标是采样后的时间轴。

完全重复帧用 RGBA 哈希匹配。近似匹配先比较 8×8 RGB 描述，搜索全部已选代表帧，最多核验距离最近的 8 个；再以完整分辨率计算全局误差、16×16 分区最大误差、变化像素比例，并拒绝任何通道差异超过 15% 的像素。每个成员直接对照固定代表帧，禁止沿相似帧链累计偏差。匹配是保守启发式，可能漏掉可复用帧，不承诺最少代表帧或感知无损。

本地评估 100、99.75、99.5、99、98.5、98 六档，也支持自定义小数阈值。自动推荐在 ≥99%、时长加权平均误差 ≤0.3% 的候选中，选择达到最少版图数的最严格档位；相同版图数时不为了更少代表帧而放宽阈值。评分由像素误差计算，不是模型识别置信度。此范围是实验保真策略，各素材的帧数、实际误差、省版数和推荐结果均现场计算。

草稿展示实际拼版张数变化、复用数量、去重前后动画、最不相似的复用帧对、完整映射与候选阈值表。近似复用可能削弱细微动作，应检查预览后再 Submit；点击其他阈值会使当前配置进入待重新预览状态。减少代表帧不一定减少版图张数，页面明确说明未节省费用的情况。重复画面使用同一张生图结果，使这些位置保持一致；不同代表帧之间的一致性仍取决于生图效果。

代表帧按首次出现顺序重新编号并拼版，生图与重试沿用现有队列。全部代表帧切图后，按保存的映射回填每个播放位置，保留逐帧时长（含 0）、帧数及循环。原帧和代表帧清单、映射、评估报告及本地预览均纳入草稿哈希；不允许提交后改变映射。还原前校验清单哈希、代表帧覆盖、生成帧尺寸和像素哈希，缺图或映射损坏时停止，不使用原图补位。单版重新生图后所有引用该版代表帧的位置同步更新，历史成品仍保留。

文件：`sampled/dedup/animation.json`、`mapping.json`、`report.json`、`preview/edited.gif`；生成的代表帧在 `representative-final*/`，还原后的完整成品仍在 `final*/`。对去重任务手动使用 `bundle.json` 只能得到代表帧集合；完整时间轴必须经过 `restoreDedup` 映射还原，不能把代表帧集合当作最终 GIF。

## 四角定位与切边

新 Web 拼版在每个有效格的四角外侧绘制四种颜色的方形标记，中心带暗点；白色分隔带至少 16 px、外边距至少 12 px。提示词要求标记和白纸保持原样。

切图时先从返回图中检测颜色连通区域，再把四个不同标记与对应格关联，测量该格的实际内容矩形，支持输出尺寸被修改及横纵不同的缩放。缺标记或四角不构成可靠矩形会停止切图并保留原始返回图，不会用猜测的矩形发布 GIF。

对于供应商缩小、重绘或压缩后发生颜色偏移的角标，固定 RGB 匹配失败时会尝试色相匹配。缩小后 2–3 像素的角标允许轻微颜色混合，并联合选择四角，以矩形对齐、尺寸、预期位置和标记不可重复使用约束排除相邻格干扰；透明度及分隔带检查仍执行，真实缺失角标不会跳过验证。

内容矩形会进一步按原帧边缘检查新增的白色分隔带，并排除约 2 个输出像素的混色过渡边，最后使用 `fit: fill` 拉伸到目标分辨率。原本白色的场景继续保持不透明，不按颜色做抠图。实际裁剪框、边缘检查和拉伸策略保存在 `crop-report.json` 中。老任务没有定位标记时仍支持白带配准及这一切边策略。

切图、输入采样和最终尺寸恢复会先验证全部像素 alpha=255，再转换为 RGB 进行缩放，避免 RGBA 重采样将 255 舍入为 254 而导致 GIF 编码失败。这不是透明图铺底或阈值处理；真正含透明度的输入仍会拒绝，GIF 编码器的半透明检查保持不变。

## 完整时间轴的抽帧建议

- 全部帧先解码为保持比例、最长边 96 px 的 RGB 缩略图；不只读取 GIF 开头。
- 最多 4 路本地 worker 并行处理完整相邻帧序列；跨分块边界的帧对同样计算，检查每一对恰好被覆盖一次。
- 同时计算整体 RGB 差异和局部块差异，避免大面积静止背景掩盖小主体动作。每个推荐档位都重新评估完整时间轴中的保持帧误差。
- 对局部活跃时间窗保留运动峰值，场景突变保留前后帧；静止段可合并为长显示帧。推荐档位记录的是具体原始帧索引，平均 FPS 仅用于说明，并不会统一应用于所有片段。
- 采样前核对分析报告的源 GIF 哈希，草稿保存索引映射和输入图快照；最终时间和循环仍与源素材一致。没有明显冗余时会保守地建议保留原帧。
- 分析状态和指标在素材目录的 `analysis-state.json`、`motion-analysis.json` 中持久保存；失败时仍可使用手动帧数/FPS 设置。

修改参数后 Submit 会停用，必须重新生成草稿。所有草稿都是独立快照，右侧任务列表可以重新打开旧草稿和结果。刷新页面不会提交任务。

## 采样行为

- GIF 像素比例字段 `0` 表示未指定，`49` 明确表示 1:1，两者都按方形像素处理，不拉伸。其他有效值按 GIF89a 的 `(值 + 15) / 64` 计算像素宽/高比；Web 预处理扩展相应轴，将显示比例转换为方形像素。分辨率档位、抽帧缩略图、预览与“放回原尺寸”均使用转换后的显示尺寸，界面会注明原始像素网格。原 GIF 不改动，原始比例与转换尺寸记录在 `sampling.json`；逐帧时长与循环保留。

- 上传或选择 GIF 后，默认填入原图尺寸和全部原帧。尺寸档位按像素面积逐级减半生成，显示实际宽高及比例，排除重复尺寸；可自定义 1 px 到原图长边的任意整数像素，不再使用通用百分比按钮或固定 5% 下限。横纵图保持宽高比（允许整数像素舍入）。尾版为利用画布可能放大单格，卡片会显示实际单格尺寸。
- “按保留帧数”可在当前 GIF 的范围内精确选择 N 帧，按时间轴选择 N 个不同的原始帧；被移除帧的时长合入前一个保留帧，保留原时间边界和总时长。帧数档位也从此 GIF 生成，例如 67 帧素材生成 67、34、17 等选项。选择全部原帧则保留原始逐帧 delay。
- 降帧率按原动画时间轴等间隔取样，不是简单地每隔 N 帧删一帧。新的帧时长按 GIF 的 10 ms 精度分配，合并重复选择的慢帧，保持原始总时长与循环次数。
- “按目标帧率”的范围按原始帧数与总时长计算，上限是原始平均 FPS；候选档位显示预计最多帧数。因整数帧数和慢帧合并，实际 FPS 可能略低于目标。单帧或全 0 时长动画保留全部帧，只开放分辨率调整；很长动画的最低帧数受 GIF 单帧时长上限约束。旧草稿的 `maxFps=0` 行为保持兼容。
- 每版帧数的手动上限随当前采样帧数更新。切换 GIF 会重置采样为新素材的原尺寸与全部原帧，避免沿用上一素材的范围。服务端同步校验这些边界。
- 最终 GIF 可选择采样分辨率，或在生成后放回原始分辨率；后者不会增加接口请求次数，也不会恢复被采样丢弃的细节。
- 默认 1280×1280 画布、16 px 分隔带和 12 px 边距；每张请求 n=1，按张数展示成本规模。

## 浏览器配置与服务端 Provider 列表

自定义 provider 可填写名称、Base URL、API Key、模型、质量和超时（1–1800 秒），支持保存、编辑、删除及切换。配置持久保存在当前站点的浏览器 `localStorage`，包含 API Key；同源其他标签页会同步变更。服务端不保存这些自定义配置，执行时由浏览器临时提交，主进程在内存中冻结配置，再通过 IPC 传给工作进程。任务文件只记录模型、质量和配置签名，自定义 endpoint 在请求记录中用 `[browser-provider]` 代替；API Key 不落盘。浏览器清除站点数据会删除配置。

服务端列表访问使用独立的 `.env` 变量：

```dotenv
GIF_LAB_PROVIDER_SECRET=自行设置的列表访问密钥
GIF_LAB_PROVIDERS='[{"id":"default","envPrefix":"OPENAI"},{"id":"backup","envPrefix":"BACKUP"}]'
BACKUP_BASE_URL=https://backup.example.com/v1
BACKUP_API_KEY=供应商密钥
BACKUP_IMAGE_MODEL=供应商模型名
BACKUP_IMAGE_QUALITY=medium
BACKUP_IMAGE_TIMEOUT_MS=300000
```

未填写列表时沿用原 `OPENAI_*` 默认条目；空列表 `[]` 表示没有服务端 provider。也可使用内联对象 `{id,baseUrl,apiKey,model,quality,timeoutMs}`。ID 必须唯一，支持最多 32 个条目。Base URL 包含接口前缀（通常 `/v1`），不能带用户名、密码、查询参数或片段。

输入正确 secret 后才可读取和选择服务端列表，列表响应只有 `{id,host}`，`host` 为域名和端口（含默认 443/80）；不展示完整路径、模型或密钥。后端在新建绑定服务端配置的草稿、Submit、单帧试生成、确认新草稿及新生图重试时再次认证，猜测 ID 不能绕过。secret 只保存在当前页面内存，刷新或点击“锁定列表”后需重新输入；不会写入 localStorage。未设置 secret 时服务端列表关闭，不回退到无认证默认 provider。

每次提交冻结其 provider；排队后切换选择不会影响该请求。首次 Submit 仍校验草稿记录的 provider 签名，更换地址、模型或质量后需重新生成草稿。已提交任务的手动重新生图/继续使用当前选择，保留原审核输入。单帧实验沿用选择：试生成使用提交时配置，确认创建的新草稿绑定确认时选择。服务重启中断任务，不会持久保存浏览器凭据或自动重发；手动继续时重新提供选择。本地重切不需要 provider 或列表 secret。

接口：`POST /api/providers` 接收 `{secret}`；任务相关 POST 可附加 `provider:{kind:"server",id,secret}` 或 `provider:{kind:"browser",config:{baseUrl,apiKey,model,quality,timeoutMs}}`。无 provider 时禁止生图，不隐式使用 `.env` 的密钥。CLI 仍按原来的 `.env` 读取方式运行。

## 启动与数据

```bash
npm ci
npm run web
```

运行时变量：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `GIF_LAB_HOST` | `0.0.0.0` | 监听地址 |
| `GIF_LAB_PORT` | `3087` | HTTP 端口 |
| `GIF_LAB_DATA_DIR` | `~/experiments/YYYY-MM-DD/gif-character-replacer-web` | 当前用户 home 下的任务与素材目录，日期按启动时的 Asia/Shanghai 日期 |

同一批实验后续重启请将 `GIF_LAB_DATA_DIR` 固定为原目录。正式代码留在本项目；资产和任务均不写入项目或模型目录。服务直接开放局域网访问，无入口口令。`.env` 只供服务端读取，API 和静态文件接口不会返回密钥。

`npm run web` 在前台启动服务；需要后台运行时可自行配置进程管理器或用户级 systemd 服务。仓库不依赖特定机器上的服务或容器，也不附带自动部署配置。

每个任务保留 `task.json`、原始 GIF、参考图快照、`sampled/sampling.json` 采样映射、`plans/` 实际提交输入、各 `edit-N/` 返回内容，以及最终 GIF 和逐帧来源报告。需要手工组装时可使用任务的 `bundle.json` 和现有 `ai-assemble` 命令。

## 提示词与逐帧约束

新草稿使用 `adaptive-pose-expression-v3` 模板，以“逐帧替换 main character，保留姿势、神态、表情并保持连贯”为核心。目标定位文字、人设补充和其他指令分别放入独立字段；即使“替换目标”填写完整句子，也不会再被直接拼进 `replace … with …` 语法中。

模板明确要求每个输出格仅对应同一原格：保持动作阶段、身体与头部朝向、肢体方向、手势、支撑点、道具接触、视线、眼睑睁闭和眨眼阶段、嘴型开合及情绪强度。禁止镜像或左右颠倒、背身变正面、复制统一表情、跨格复用姿势、自动补动作或抹掉动作极值；背景、构图、镜头、其他角色、道具、文字、格子顺序及角标均保持。

原帧决定动作和表情；人设图只决定身份和外观；基准帧只补充已确认的角色设计、材质、画风和光照处理，不能把基准帧的眼睛、嘴型或姿势覆盖到其他原帧。每版卡片下方可展开“查看本版实际发送的完整提示词”，读取经过哈希核对的落盘快照与版本号。旧草稿及历史请求不修改；需要新提示词时创建新草稿再审核。

这些是发送给生图模型的明确约束，不是对模型动作保持能力的保证。本地测试验证输入角色分工、提示词内容和快照一致性，实际效果仍需单帧试生成及整段预览审核。

## 提交与中断

遇到 HTTP 5xx 且没有保存到图片时，单版显示“结果待确认”，并显示实际请求耗时。504 只表示某一层网关等待失败，不能据此认定供应商没有生成；先核对供应商请求记录，避免重复计费。本地请求超时与上游网关超时是不同限制，提高本地等待时间不会解除供应商的网关限制。

每次请求保存 `clientRequestId` 并以 `X-Client-Request-Id` 发送；失败时将供应商错误结构和允许保留的追踪响应头写入 `provider-error-response.json`，密钥会被脱敏。SDK 的“no body”不一定表示 HTTP 响应为空，非标准 JSON 中的顶层信息也会保留。若 HTTP 5xx 响应中实际包含一张完整 base64 图片，保存图片并执行正常校验、切图，不发送第二次请求，原 HTTP 状态仍被记录。只有错误信息或结果链接时不会自动重新生成或随意下载。

旧版本未保存的错误响应无法事后重建。若本地没有图，需要供应商请求号或已有结果链接进一步核对；本地任务 UUID 不是供应商请求号。

- 提交校验审核版本、所有输入哈希和模型配置。服务端也会拦截旧版本和并发重复提交；同一草稿最多排队一次。
- 本地预处理与接口执行在独立子进程中完成，长时间生图不会阻塞状态查询。多个任务的图片请求共享全局并发上限。
- 请求禁用自动重发；返回图尺寸有偏差时自动尝试定位标记或旧版白色分隔带算法恢复，不用 LLM 定位切图。配准矩形向内取整时，留白校验排除内容边缘的 2 px 舍入区域，实际裁剪仍采用紧边界与 `fill` 拉伸。
- 失败会取消该任务尚未发出的排队请求，等待已发出的请求保存结果后显示失败。服务重启时，未完成任务会标为中断，不会自动重新提交。用户可选择本地重切、单版重新生图或继续；操作 ID 防止同一次提交重复排队。
- 首次 Submit 要求模型、质量及上游地址与草稿审核时一致，否则需新建草稿。已提交任务的手动重新生图和继续使用当前配置，记录本次接口身份；原审核输入和哈希保持不变。单纯更新 API Key 不改变草稿参数。

## 验证与范围

自动化测试覆盖原有处理链、动态采样参数、定位标记缩放及缺失、白边排除与真实白底保留、并发完整时间轴覆盖、长静止开头后的高速动作保留、智能索引快照、重复提交、接口失败和服务重启。浏览器验证上传、分析状态、智能档位、拼版预览、模拟提交及草稿回读；验证不发送真实图片请求。四角标记的定位算法已经用本地模拟输出验证，实际模型保留标记的效果需在用户审核后的提交中观察。

当前支持不透明显示帧（包括纯白背景）；透明 GIF 会明确报错。上传 GIF 上限 100 MiB，解码 RGBA 总量上限 512 MiB。0 时长动画不能按时间降帧率，可保留原帧。GIF 编码仍使用逐帧量化基线，最终体积压缩与单帧角色精修不属于本次改动。

接口沿用项目的 Images Edits 调用，参考 [OpenAI 图片生成与编辑文档](https://developers.openai.com/api/docs/guides/image-generation)。
